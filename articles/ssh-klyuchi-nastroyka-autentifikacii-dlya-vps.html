SSH-ключи: настройка аутентификации для VPS — полное руководство

SSH-ключи — это самый надёжный способ аутентификации на вашем VPS-сервере. В отличие от паролей, которые можно подобрать или перехватить, криптографические ключи обеспечивают практически непробиваемую защиту. В этом руководстве мы разберём, как настроить SSH-ключи для VPS, как сгенерировать пару ключей, добавить публичный ключ на сервер и отключить устаревший парольный вход.

Если вы администрируете свой собственный сервер — будь то для сайта, бота или личного VPN, — настройка SSH-ключей обязательна. Это первая линия обороны от брутфорс-атак и несанкционированного доступа.

Что такое SSH-ключи

SSH (Secure Shell) — это протокол для удалённого управления сервером. SSH-ключи — это пара криптографических ключей: публичный (public key) и приватный (private key). Публичный ключ вы размещаете на сервере, а приватный храните у себя на компьютере — и никогда никому не передаёте.

Когда вы подключаетесь к серверу по SSH, сервер проверяет, что у вас есть соответствующий приватный ключ. Если проверка проходит — доступ открывается. Никакой пароль не нужен.

🔑 Как это работает:

  • Асимметричное шифрование — используется пара ключей: публичный и приватный.
  • Цифровая подпись — сервер отправляет запрос, клиент подписывает его приватным ключом.
  • Никакой передачи секретов — приватный ключ никогда не покидает ваш компьютер.

Почему SSH-ключи лучше паролей

Многие администраторы до сих пор используют пароль для входа на VPS. Это опасная практика. Вот почему:

  • Пароль можно подобрать — брутфорс-атаки перебирают миллионы комбинаций в минуту.
  • Пароль можно украсть — фишинг, кейлоггеры, утечки баз данных.
  • Пароль можно забыть — а восстановление доступа к VPS — это всегда головная боль.
  • SSH-ключи не подвержены брутфорсу — подобрать 2048-битный ключ невозможно даже при самых мощных вычислительных ресурсах.
"Использование SSH-ключей вместо паролей снижает риск взлома вашего сервера на 99,9%. Это стандарт индустрии, которому следуют все профессионалы." — из руководства по безопасности VPS.

Генерация SSH-ключей

Для генерации SSH-ключей используется встроенная утилита ssh-keygen. Она есть на всех Linux, macOS и даже в Windows (через WSL или Git Bash).

1 Откройте терминал на вашем локальном компьютере.

2 Выполните команду:

ssh-keygen -t ed25519 -C "ваш-email@example.com"

Используем Ed25519 — современный и безопасный алгоритм. Если ваш сервер не поддерживает его (что маловероятно), используйте rsa -b 4096.

3 Укажите путь сохранения (можно оставить по умолчанию, нажав Enter).

4 Задайте парольную фразу (passphrase) — это дополнительная защита приватного ключа. Можно оставить пустым, но с паролем безопаснее.

После выполнения команды в указанной директории (~/.ssh/) появятся два файла:

  • id_ed25519 — приватный ключ (никогда не передавайте его никому!)
  • id_ed25519.pub — публичный ключ (его можно и нужно размещать на серверах)

Добавление публичного ключа на VPS

Теперь нужно поместить ваш публичный ключ на сервер. Есть два способа:

Способ 1: Автоматический (рекомендуемый)

ssh-copy-id username@ваш-ip-адрес

Введите пароль пользователя на сервере — и ключ будет скопирован автоматически.

Способ 2: Ручной

1 Подключитесь к серверу по SSH с паролем.

2 Создайте директорию .ssh (если её нет):

mkdir -p ~/.ssh

3 Откройте файл authorized_keys для редактирования:

nano ~/.ssh/authorized_keys

4 Вставьте содержимое вашего публичного ключа (файл id_ed25519.pub) в этот файл. Сохраните и закройте.

5 Установите правильные права доступа:

chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys

Отключение парольного входа

После того как вы убедились, что вход по ключу работает, обязательно отключите вход по паролю. Это закроет главную лазейку для злоумышленников.

1 Откройте конфигурационный файл SSH:

sudo nano /etc/ssh/sshd_config

2 Найдите и измените следующие параметры:

PasswordAuthentication no
PermitRootLogin prohibit-password
ChallengeResponseAuthentication no

3 Сохраните файл и перезапустите SSH:

sudo systemctl restart sshd

⚠️ Важно:

Перед отключением парольного входа убедитесь, что вы можете зайти по ключу в новой сессии. Если что-то пойдёт не так, вы не потеряете доступ к серверу. Держите второе окно терминала открытым на всякий случай.

Дополнительные меры безопасности

Настройка SSH-ключей — это база. Но для полной защиты VPS стоит добавить ещё несколько шагов:

  • Смените стандартный порт SSH (22 на что-то другое, например 2222) — это снизит количество брутфорс-атак.
  • Настройте Fail2Ban — автоматическая блокировка IP после нескольких неудачных попыток входа.
  • Используйте двухфакторную аутентификацию (2FA) — дополнительный слой защиты даже для ключей.
  • Регулярно обновляйте сервер — sudo apt update && sudo apt upgrade.
  • Настройте брандмауэр (UFW/iptables) — разрешайте только необходимые порты.
