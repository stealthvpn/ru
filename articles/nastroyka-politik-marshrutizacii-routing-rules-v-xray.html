Настройка политик маршрутизации (Routing Rules) в Xray: полное руководство

Одной из самых мощных функций Xray является гибкая система маршрутизации (routing). Она позволяет направлять трафик по разным каналам в зависимости от домена, IP-адреса, протокола, страны и множества других параметров. Правильно настроенные политики маршрутизации не только повышают производительность, но и делают ваш прокси-сервер практически невидимым для систем DPI. Что такое маршрутизация в Xray

Xray (форк проекта V2Ray) предоставляет возможность гибко управлять потоками данных. Routing rules (правила маршрутизации) определяют, через какой исходящий прокси (outbound) будет отправлен тот или иной пакет. Это позволяет решать задачи:

  • Направлять трафик к определённым сайтам через разные прокси-серверы.
  • Обходить блокировки DPI, маскируя трафик под обычный HTTPS (с помощью XHTTP + Reality).
  • Оставлять локальный трафик (например, в локальной сети) вне прокси.
  • Балансировать нагрузку между несколькими серверами.

Правила маршрутизации обрабатываются последовательно сверху вниз. Когда правило совпадает, трафик направляется в соответствующий outbound. Если ни одно правило не подошло, используется default outbound (обычно это основной прокси).

Структура конфигурации routing

В файле конфигурации Xray (config.json) секция routing выглядит так:

{
  "routing": {
    "domainStrategy": "AsIs",
    "rules": [
      {
        "type": "field",
        "domain": ["example.com"],
        "outboundTag": "proxy"
      },
      {
        "type": "field",
        "ip": ["geoip:private"],
        "outboundTag": "direct"
      }
    ]
  }
}

Ключевые параметры:

  • domainStrategy — стратегия обработки доменов (AsIs, IPIfNonMatch, IPOnDemand).
  • rules — массив правил, каждое содержит условие (domain, ip, protocol, port, network и др.) и outboundTag — имя исходящего соединения.

В Xray также поддерживается balancer — балансировщик, который может распределять трафик между несколькими outbound.

Типы правил (domain, ip, protocol, и др.)

Рассмотрим основные условия, которые можно использовать в правилах:

  • domain — список доменов (или поддоменов). Поддерживаются точные совпадения, регулярные выражения и специальные префиксы (domain:example.com, regexp:.*\.example\.com).
  • ip — список IP-адресов или подсетей. Можно использовать geoip:ru (все IP-адреса России) или geoip:private (локальные адреса).
  • protocol — протокол прикладного уровня (например, http, tls, bittorrent).
  • port — порт назначения (один или диапазон).
  • network — тип сети (tcp, udp, tcp,udp).
  • source — источник трафика (IP или порт клиента).
  • inboundTag — тег входящего соединения, чтобы применять правила только для определённых входов.

Также есть составные правила с использованием and или or (через массив условий).

Практические примеры конфигураций

Пример 1: Проксирование только заблокированных сайтов

{
  "routing": {
    "domainStrategy": "IPOnDemand",
    "rules": [
      {
        "type": "field",
        "domain": ["facebook.com", "twitter.com", "youtube.com"],
        "outboundTag": "proxy"
      },
      {
        "type": "field",
        "ip": ["geoip:private"],
        "outboundTag": "direct"
      }
    ]
  }
}

Здесь все запросы к указанным доменам идут через proxy, а локальный трафик — напрямую.

Пример 2: Обход DPI с использованием XHTTP + Reality

{
  "routing": {
    "domainStrategy": "AsIs",
    "rules": [
      {
        "type": "field",
        "domain": ["geosite:google", "geosite:youtube"],
        "outboundTag": "xhttp-reality-out"
      },
      {
        "type": "field",
        "protocol": ["bittorrent"],
        "outboundTag": "direct"
      }
    ]
  }
}

Все запросы к Google и YouTube направляются через outbound с технологией XHTTP + Reality, а торренты идут напрямую (чтобы не перегружать прокси).

Пример 3: Маршрутизация по странам (geoip)

{
  "routing": {
    "domainStrategy": "IPIfNonMatch",
    "rules": [
      {
        "type": "field",
        "ip": ["geoip:ru"],
        "outboundTag": "direct"
      },
      {
        "type": "field",
        "ip": ["geoip:us"],
        "outboundTag": "proxy-us"
      },
      {
        "type": "field",
        "network": "udp",
        "outboundTag": "direct"
      }
    ]
  }
}

Трафик к российским IP идёт напрямую, к американским — через американский прокси, UDP — напрямую.

Маршрутизация через XHTTP + Reality

Технология XHTTP + Reality позволяет маскировать VPN-трафик под обычный HTTPS-запрос к легитимному сайту. DPI-системы видят ваш трафик как обычный браузер Chrome, и не могут отличить его от обычного веб-сёрфинга. Это идеальное решение для стран с жёсткой фильтрацией.

🔑 Как настроить маршрутизацию через XHTTP + Reality:

  • Создайте outbound с типом vless или vmess, указав параметры flow: "xtls-rprx-vision" и настройки Reality.
  • В секции routing добавьте правило, которое направляет нужный трафик (например, все домены, которые должны быть скрыты) в этот outbound.
  • Используйте domainStrategy: "IPIfNonMatch" для корректного разрешения доменов.

Пример outbound для XHTTP + Reality:

{
  "outbounds": [
    {
      "tag": "xhttp-reality-out",
      "protocol": "vless",
      "settings": {
        "vnext": [
          {
            "address": "your-server.com",
            "port": 443,
            "users": [
              {
                "id": "ваш-uuid",
                "flow": "xtls-rprx-vision",
                "encryption": "none"
              }
            ]
          }
        ]
      },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",
        "realitySettings": {
          "show": true,
          "dest": "www.microsoft.com:443",
          "serverNames": ["www.microsoft.com", "*.microsoft.com"],
          "privateKey": "..."
        }
      }
    }
  ]
}

При таком подходе DPI видит только TLS-рукопожатие с www.microsoft.com, а внутри передаётся ваш защищённый трафик.

Советы по оптимизации правил маршрутизации

  • Используйте гео-базы данных (geoip и geosite) для упрощения настройки правил по странам и популярным сервисам.
  • Не перегружайте правила — слишком много условий замедляют обработку. Объединяйте похожие домены в один список.
  • Тестируйте конфигурацию с помощью xray run -test перед применением.
  • Используйте domainStrategy: "IPIfNonMatch" — если домен не разрешается, Xray попытается использовать IP-адрес.
  • Для повышения производительности включайте кэширование DNS в настройках Xray.
